# Slasher · Boss 01「圣骑士」—— 竞技场单挑原型

一个人、一把太刀、一个三阶段的 Boss。范围锁死在**一场战斗**里：不做过关、不做成长、不做第二把武器。
目标是把「一个 Boss 的读招与应对」打磨到能反复打、且每一步都能说出依据。

- **看：** [`boss-demo.mp4`](boss-demo.mp4)（51.5 s，实机录制）
- **玩：** 下载 [`BossArena-webgl.zip`](BossArena-webgl.zip)，解压后在目录里起一个静态服务（见下）
- **数据与取舍：** 本文「三处设计取舍」「与设计稿的差异」「验证」三节

## 怎么跑

```bash
unzip BossArena-webgl.zip -d boss && cd boss
python3 -m http.server 8000   # 浏览器打开 http://localhost:8000
```

必须用 `http://` 起服务，直接双击 `index.html` 会被浏览器的本地文件策略挡住（wasm 加载失败）。

## 玩法

玩家固定 200 血，进场自动锁刀（妖刀村雨）。**本战只给四件手段：普攻 / 弹反 / 居合 / 闪身步** —— 这不是删减，
是前提：每招都要有明确解，手段一多就变成「总有一招能盖过去」，读招失去意义。

| 阶段 | 触发 | 内容 |
|---|---|---|
| 一阶段：持盾 | 开场 | Boss 持盾，攻击不掉血。破盾两条路：把冲撞引到柱子上，或弹反四次把盾打飞 |
| 二阶段：金色形态 | 盾破 | 盾消失，改投电矛、放电波、留电场桩。没有破盾这种「大窗口」，输出只能从前摇后摇里抠（每招 ≥ 0.4 s） |
| 狂暴 | 血量 50%，一次 | 追加电矛、铁索连环、三连冲撞、引爆全场，整体提速 ×0.85 |

**柱子是消耗品**：6 根、每根 3 次耐久，被 Boss 攻击命中 −1，被冲撞命中直接断。A 路径（撞柱破盾）烧掉掩体，
B 路径（弹反四次）不消耗场景资源 —— 两条路各有代价，柱子打光也不会死局。

## 键位

| 键 | 作用 |
|---|---|
| `WASD` | 移动 |
| `Shift` | 疾跑（×1.7） |
| `J` | 普攻（三段连击） |
| `K` | 弹反（窗口 0.18 s，冷却 0.6 s） |
| `I` | 居合：穿过对手落到身后回身重击，穿过期间无敌 |
| `O` | 闪身步：位移 5 m，落点 0.15 s 无敌帧，冷却 2 s |
| `Q` | 锁定最近敌人 |
| `V` | 切换第三人称 / 俯视机位 |
| `F2` | 自动玩家（右上角实时显示每个技能的「用 / 中 / 伤害」） |

## 三处设计取舍

**1. 破盾走两条路，而不是一条。** 单路径的破盾会把 Boss 变成「按流程走一遍」；两条路径各自消耗不同的东西
（场景资源 vs. 操作精度），玩家得自己选。柱子被打光不死局，因为 B 路径不依赖场景。

**2. 冲撞方向锁在前摇开始，不是结束。** 锁在结束时，侧移一步就能躲，柱子永远撞不到，A 路径直接失效。
锁在开始，玩家必须站到「柱子正好在自己身后」的位置起手 —— 把一个闪避动作变成了站位问题。

**3. 二阶段把眩晕与破盾全拿掉。** 一阶段的输出窗口是「破盾后的 5–10 s」，二阶段没有这种东西，
只能给每招定一个可打时长（都 ≥ 0.4 s）。窗口短而密，玩家必须打两下就走 —— 节奏从「攒一波爆发」
变成「连续抠缝」。

## 与设计稿的差异

设计稿写在先、实现在后，两边分叉了六处。逐条列出，因为差异本身就是设计过程：

| 项 | 设计稿 | 实现 | 原因 |
|---|---|---|---|
| 投矛触发距离 | ≥ 30 m | ≥ 18 m | 玩家没有远程手段，不会主动跑到 30 m 外 |
| 投矛数量 | 3 发 | 18 根（3 × 2 × 3） | 单发弹幕没有压迫感，改成大波套小波 |
| 弹反破盾后窗口 | 硬直 1.2 s | 眩晕 10 s | B 路径要贴身弹反四次，窗口给宽才值得 |
| 电矛桩上限 | 3 根 | 15 根 | 桩是场控资源，上限高一些才谈得上「骗掉」 |
| 铁索连通 | 全部两两相连 | 只连 ≤ 12 m | 15 根全连是 105 条边，场地会变成电网 |
| 落雷落点 | Boss→玩家方向 7 m 固定点 | 玩家脚下（不追踪） | 前推 7 m 对站着不动的玩家完全无效，且落点没有阅读规律 |

## 验证

不靠「看着没问题」交付。三套自动断言跑在同一套真实逻辑上（不走旁路）：

| 套件 | 条数 | 覆盖 |
|---|---|---|
| 场景冒烟 | 79 | 场地边界与柱位、蓄量槽、每招前摇与闪烁窗口、落雷落点、破盾路径记录、阶段转换与无敌、狂暴阈值与提速、锁刀后各刀技可用性 |
| 音频 | 54 | 17 个音效 id 的绑定、池化、去重、缺 clip 时不报错 |
| 姿态 | 86 | 11 段 Boss 姿态 × 盾/矛/手/脚不穿地、事件与循环、骨骼链、俯视幅度补偿 |

一条命令跑完：`./Tools/verify-arena.sh`（重建场景 → 79 → 54 → 86 → 三张 1600×900 截图）。

**一个从数据里读出来的结论：** 自动玩家跑 10 场，落雷 554 次出手命中 548 次（≈99%），
因为脚本玩家只在判定前 0.18 s 才动，0.7 s 的预警它吃不下去；人类提前走位则出得去（6 m/s × 0.7 s = 4.2 m > 判定半径 3 m）。
所以落雷是「惩罚走神」的招，不是「惩罚不会交位移」的招 —— 这条直接决定它没有被改成必吃招。

## 已知限制

- **单 Boss、单武器、单场景。** 这是范围选择，不是未完成：原型的验证目标是「一场战斗能不能立住」。
- **没有开始界面与设置。** 键位写在本文，音量暂不可调。
- **无存档。** 一场打完重开即可，原型阶段没有需要保留的状态。
- **柱子不重生**，靠 B 路径兜底。
- **落雷预警 0.7 s 仍偏宽松**：要真正逼出闪身步的无敌帧，预警得压到 ≈0.45 s 以下，这一版没有那么做。

## 工程

Unity `6000.3.25f1`，核心逻辑与表现层分离（`BossCore` 是纯逻辑，不引用 `UnityEngine`；表现层 `BossFight` 只负责读状态与播动画）。
姿态动画为代码驱动的关键帧表（22 骨、11 段 Boss / 10 段玩家），不用 Animator —— 因为它需要能被断言、被 diff、被单人维护。
